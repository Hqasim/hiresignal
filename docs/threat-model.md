# Threat model

**Status:** as of 2026-10-12, every control below is built, tested and deployed (SPEC §18). The measured results are in [`evals.md`](evals.md); the fairness side of the same controls is in [`responsible-ai.md`](responsible-ai.md).

HireSignal reads resumes written by people who have a reason to game it, and sends parts of them to a third-party model. This document lists what can go wrong, maps each threat to the [OWASP Top 10 for LLM Applications (2025)](https://genai.owasp.org/llm-top-10/), and names the control and the code that implements it.

## Assets and trust boundaries

| Asset                                                                 | Why it matters                                                                                                  |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Candidate PII (names, contacts, addresses, schools, graduation years) | Blind screening is the product's promise, and the Gemini free tier may use prompts to improve Google's products |
| Scores and guard verdicts                                             | A manipulated score is the attack an applicant wants                                                            |
| The Gemini key and its daily quota                                    | Exhausting it takes the demo down                                                                               |
| The database (Neon)                                                   | It holds every verdict and scorecard                                                                            |

Untrusted inputs:

- **Resume text:** the applicant controls it fully, including invisible characters and markup.
- **Recruiter questions:** the public demo has no authentication.
- **Model output:** treated as untrusted until Zod has parsed it and code has checked it.

Also in scope:

- The public API is unauthenticated by design: synthetic, read-mostly demo data. That includes `/api/ops/summary` and `/api/ops/calls`, which expose call metadata (tasks, models, tokens, latency, random request ids) and never content.
- `/api/docs` loads Swagger UI from jsDelivr pinned with Subresource Integrity, under a CSP that allows only those files and its own inline script ([ADR 0021](adr/0021-openapi-document-from-contracts.md)).
- CORS allows only the Amplify origin.
- Secrets live only in GitHub Environments and Lambda env vars ([ADR 0016](adr/0016-secrets-via-github-environments.md)). CI never receives the Gemini key, and deploys assume an AWS role through OIDC, so no long-lived AWS key exists.
- The Lambda connects as `hiresignal_app`, which can select, insert and update but not delete or create ([`0002_app_role_grants.sql`](../db/migrations/0002_app_role_grants.sql)). Only migrations and the reseed use the owner role.
- [Dependabot](../.github/dependabot.yml) proposes npm and GitHub Actions updates weekly, [CodeQL](runbook.md#codeql) scans every push and pull request, and `main` accepts changes only through a pull request with all six CI checks green ([runbook, Branch protection](runbook.md#branch-protection)).
- Visitors can change the public demo (shortlist, re-screen). A nightly replay reseed resets it, with zero model calls ([ADR 0024](adr/0024-e2e-on-replay-stack-and-read-only-production-smoke.md)).

## Detection results

As of 2026-10-12, on the 40-item injection set (`data/evals/injection.jsonl`), measured by `npm run eval` ([generated tables](evals.md#injection)):

| Arm                        | Attacks detected | Benign flagged | Attacks quarantined |
| -------------------------- | ---------------- | -------------- | ------------------- |
| Rules only (L0–L2)         | 18/20            | 4/20           | 5                   |
| Rules + classifier (L0–L3) | 20/20            | 0/20           | 20                  |

- The rules miss the two paraphrased social-engineering attacks (M19, M20), which is why L3 exists. They flag four benign items: three engineers describing injection defenses and one ordinary template comment.
- The classifier catches both misses and clears all four false positives.
- On the ten seeded resumes, the rules alone quarantine C06 (hidden markup); the classifier quarantines C07 (an instruction in plain sight, `malicious` 1.00) and clears the medium signals of C02 (security vocabulary) and C10 (stray zero-width spaces).
- CI gates malicious recall at 1.00 and the benign false-positive rate at ≤ 0.05 ([ADR 0023](adr/0023-evals-as-ratcheting-ci-gates.md)).

## Known limits

**Ask questions** (SPEC §9.7):

- The question guard has no classifier. A visible, paraphrased instruction in a question reaches the answer model, spotlighted as `<untrusted_question>`. The asker sees only their own answer, and every citation in it is still verified.
- The answer's prose isn't verified, only its citations. The prompt requires a citation for every claim, and an answer with no verified citation is withheld.

**Redaction** (SPEC §9.3, ADR 0014):

- Names that aren't in the `# Name` heading (a referee, a cofounder, a nickname) aren't redacted.
- Only US street formats and `City, ST 12345` are detected. Non-US addresses, and a city and state without a ZIP, survive.
- Schools and years are redacted only in the Education section. A university named in Experience is kept as job evidence.
- PII inside images or attachments is out of scope; resumes are Markdown text.

**Injection detection** (SPEC §9.4, ADR 0013):

- The rules are English-centric, and a determined paraphrase beats them. L3 exists for that case, and spotlighting plus code-side scoring limit the damage of a miss.
- NFKC folds fullwidth and ligature forms, but not cross-script homoglyphs (Cyrillic "о" for Latin "o").
- Hidden-markup detection reads inline styles only. External or `<style>` block CSS, nested elements with the same tag name, and colours given as `hsl()` or named colours other than white aren't evaluated.
- The classifier reads attacker-controlled text. It runs only when no high signal exists, and it can't overrule one.
- Ingested resumes are capped by the request body limit. Every rule quantifier is bounded, so scans stay linear.
