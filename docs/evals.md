# Evals

HireSignal's claims (blind screening, injection resistance, evidence-backed scores, grounded answers) are measured by four eval suites. They run offline on every push as CI gates (SPEC §14, [ADR 0023](adr/0023-evals-as-ratcheting-ci-gates.md)). The results below are generated by `npm run eval -- --write`, never typed by hand.

## How it runs

`npm run eval` seeds nothing itself. It reads the job that `npm run seed` loaded, plus the eval sets in [`data/evals/`](../data/evals/). Every model call replays a recorded fixture ([ADR 0009](adr/0009-record-replay-llm-adapter.md)), so a run is deterministic and makes zero live calls:

```powershell
npm run db:up; npm run db:migrate; npm run seed
npm run eval                 # prints the tables; exits 1 if a gate fails
npm run eval -- --write      # also replaces the results block of this file
```

In CI, the `evals` job runs the same commands against a Postgres service container and posts the tables to the job summary. The code is in [`apps/api/evals/`](../apps/api/evals/): one pure module per suite, [`thresholds.ts`](../apps/api/evals/thresholds.ts) for the gates, and [`main/eval-wiring.ts`](../apps/api/src/main/eval-wiring.ts) for the wiring.

## Suites

| Suite      | Dataset                                                                                                                                                                                                                                                                                                                     | Measures                                                                                                                    | Ablation                                                       |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Retrieval  | `retrieval.jsonl`: 20 recruiter questions with the candidates that answer them, plus 3 that nothing in the pool answers                                                                                                                                                                                                     | recall@5 (expected candidates among the top 5 chunks' owners) and MRR; where the similarity floor falls; how each ask ended | Hybrid keyword matching `all` and `any` vs vector only (`off`) |
| Injection  | `injection.jsonl`: 20 attacks (instruction override, role hijack, evaluator targeting, output forcing, delimiter spoofing, hidden markup, Unicode tag smuggling, paraphrased social engineering) and 20 benign hard negatives (security engineers describing injection defenses, quoted errors, "ignore" in ordinary prose) | Precision, recall, F1 on the attacks; false-positive rate on the benign items; quarantines                                  | Rules only (L0–L2) vs rules + classifier (L0–L3)               |
| PII        | `pii.jsonl`: 15 snippets with 44 labelled entities across all 7 types; and the header names of the 10 seeded resumes                                                                                                                                                                                                        | Labelled values or name words left after redaction (leaks); recall per type                                                 | –                                                              |
| Scorecards | Every stored scorecard of the seeded job                                                                                                                                                                                                                                                                                    | Coverage, schema, citations re-verified, evidence behind each rating, scores that recompute                                 | –                                                              |

**What "detected" means.** The injection suite counts an item as detected when the guard flags or quarantines it. Both are visible to the recruiter. A quarantined resume is never indexed or scored; a flagged one is scored but marked for review. The quarantine count is reported separately, because it is the stricter outcome ([ADR 0013](adr/0013-layered-injection-defense-and-quarantine-policy.md)).

**The rules + classifier arm is ingestion itself.** Each item goes through the same steps as a resume: L0 on the raw text, NFKC, redaction, L1 and L2. The classifier runs unless a high-severity signal already quarantines. The rules-only arm applies the same policy with no classifier verdict.

## Gates

The gates live in [`thresholds.ts`](../apps/api/evals/thresholds.ts). Each one started one measurable step below the first result (one question or one item, on sets this small), or at the SPEC §14 bar where that is stricter, and **gates only ratchet up**. Lowering one needs an ADR that says what changed.

- **Retrieval:** recall@5 ≥ 0.95 and MRR ≥ 0.90, on the mode ask uses (`any`).
- **Injection:** malicious recall = 1.00 and benign false-positive rate ≤ 0.05, on rules + classifier.
- **PII:** zero leaks.
- **Scorecards:** 100% on every check. These are invariants of the pipeline ([ADR 0012](adr/0012-deterministic-scoring-with-verified-citations.md)), not quality targets.

## Limits

- **The retrieval set is saturated.** With 8 retrievable candidates and the top 5 chunks, recall@5 = 1.000 says little about quality. Treat it as a regression gate. Harder questions are future work.
- **The sets are small and hand-written.** 40 injection items can show that a layer catches each attack family. They can't show a rate that holds for attacks nobody wrote down. The threat model lists the known gaps ([`threat-model.md`](threat-model.md), Known limits).
- **Replay measures the recorded behaviour.** A new model or prompt is measured only after its fixtures are re-recorded (`npm run seed:record`, which also records any missing classifier verdicts through `npm run eval -- --mode record`).
- **Scorecard integrity isn't scoring quality.** It proves every stored claim is backed by a real quote and a reproducible score. Whether a rating is fair still needs a human. That is why nothing is auto-rejected.
